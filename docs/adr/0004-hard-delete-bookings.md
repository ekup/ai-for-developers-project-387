# Жёсткое удаление отменённых записей

**Статус**: accepted

Отмена записи владельцем удаляет строку из `bookings` жёстко. Слот, который занимала запись, немедленно освобождается: `occupiedIntervals` и `UpcomingBookings` не меняются, отменённая запись просто перестаёт существовать. Альтернатива — мягкое удаление по образцу типов событий (`docs/adr/0001`) — отвергнута. Основание мягкого удаления типов событий здесь не действует: на запись ничто не ссылается, её история не запрашивается ни одним сценарием, а прошлые встречи владельцу и так не показываются. При этом мягкое удаление добавило бы фильтр `deleted_at IS NULL` в запросы занятости и предстоящих встреч — цена ошибки в котором «отменённая запись продолжает занимать слот», — и потребовало бы миграции существующих БД на новую колонку, тогда как у схемы (`store/schema.go`) сейчас нет механизма миграций, только идемпотентный `CREATE TABLE IF NOT EXISTS`.
